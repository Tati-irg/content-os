## Протоколы

В новом checkout используй текущие [рендер](../../renderer/README.md) и [публикатор](../../publisher/README.md). Для диагностики ограничься локальной сборкой и проверкой. Dry run публикатора выполняет локальную проверку. Внешняя запись требует проверенного пакета и отдельного разрешения на выпуск.

## Повторы и темы для «Плана на неделю»

- [архивный REGISTRY.md](repeat/REGISTRY.md) — исторические темы, кейсы, углы и крючки.
- [архивный THEMES.md](repeat/THEMES.md) — историческая разметка больших тем по неделям.

Оба файла — архивные снимки на 9 ноября 2026. Снимок не подтверждает выходы после 9 ноября 2026. Используй их для предварительной сверки тем. Запись в плане или отсутствие записи в снимке сами по себе не показывают, вышел ли материал.

## Голос и редактура

- [Публичный профиль голоса](VOICE_PROFILE.md) — рабочая версия правил речи, ритма, юмора, подачи и стоп-листа для новых черновиков. Для авторских текстов Таты замечания передаются отдельно на согласование.
- [Сценарий и озвучка](voice/SCRIPT_VS_SPOKEN.md) — архивное сравнение редакционных версий.
- [voice_check.py](voice/voice_check.py) — локальная проверка текста на штампы. Из корня репозитория запусти `python3 docs/content-os/voice/voice_check.py путь/к/черновику.txt`. Скрипт читает текст и выводит замечания. Код 0 означает отсутствие замечаний, требующих правки, код 1 означает, что такие замечания есть.
- Полный `VOICE_PROFILE.md` содержит личные сведения и хранится отдельно. Используй согласованную копию с ограниченным доступом.

## Визуал и видео

- [TEMPLATES.md](visual/TEMPLATES.md) — правила вёрстки T01–T03. Рабочий рендер и проверка лиц находятся в [renderer](../../renderer/README.md).
- [CATALOG.md](visual/CATALOG.md) — открытый указатель ID фотобанка по снимку на 9 ноября 2026.
- [palette.js](visual/palette.js) — архивный скрипт с исходными HEX-значениями. Он сохранён для справки и содержит путь к браузеру из прежней среды. Исходный `PALETTE.png` отсутствует.
- `USAGE.md`, `photo_usage.py` и `grid_preview.py` отсутствуют в восстановленном архиве и в текущем репозитории. Для сверки ротации нужен подтверждённый журнал использования, а для визуального контроля сетки — рабочий инструмент или согласованный ручной просмотр.

## Какие входы нужны отдельно

| Роль | Чего нет в общем комплекте нового checkout |
| --- | --- |
| Исследования 01–05 и «Проверка науки» | Выгрузки постов и метрик, сырые выборки и отчёты, рабочие разборы конкурентов, `liked/INDEX.md`, подборки первоисточников и фактчеки конкретных материалов. Шпаргалка ветки науки находится в восстановленном архиве. |
| «План на неделю» и 10 | Отчёты 01–05 текущего цикла, недельные планы, подтверждённый журнал выходов и корпус исходных текстов в `runs/`. В восстановленном архиве есть `repeat_check.py`. Текстовая проверка этим скриптом требует отдельного корпуса. |
| «Запуск» и «Аудит 2» | Полный профиль голоса, разбор стиля и памятка по структуре кейсов хранятся отдельно. Тексты, записи, фактчеки и карточки конкретных материалов передаются отдельно. |
| Сборка 09, «Ролики» и «Лабуда» | Для работы с фото и видео нужны оригиналы ACTIVE, исходные записи и актуальный учёт фото. Полный каталог с описаниями кадров хранится отдельно. Исполняемый рендер и проверка лиц уже есть в `renderer/`. |
| «Публикации по расписанию» | Нужны пакет конкретного выпуска, слот, финальная версия и решения Таты по GATE 1 и GATE 2. Подтверждённый результат GATE 3 берётся из журнала выходов. |
| Сайт, позиционирование и практика | Справочные материалы и подтверждённые цены, условия и планы ведутся отдельно. |

Ссылки на старые `runs/`, `liked/`, шаблонные PNG и личные материалы в протоколах описывают прежнее окружение. Укажи недоступный вход в передаче по роли.
