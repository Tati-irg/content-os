# Передача результатов между чатами

| Откуда → куда | Что передать |
| --- | --- |
| 01–05 → «План на неделю» (06) | ID исследования, период, выборку, источники, наблюдения и ограничения. Добавь сигналы для 06. |
| 06 + 10 → Тата (GATE 1) | Стратегическую карточку, маршрут A/A-Reel/B/C, проверку тем и ограничения. Передача в производство после подтверждения. |
| 06 → 07 или 09 | Одобренную карточку и версию. A/A-Reel/B получает 07, C получает 09. |
| 07 или 09 → 08 → автор версии | Точную версию, список утверждений, источники и применимые проверки. 08 возвращает ID, вердикт и правки автору. |
| 07 → 09 для маршрута B | Проверенную версию после финальной правки, структуру и текст слайдов, подпись и результаты проверок. Если 09 меняет утверждение, версия возвращается в 08. |
| 07 или 09 → «Запуск» → Тата (GATE 2) | Финальный материал, версию, результаты фактчека и контроля качества, нерешённые вопросы. |
| «Запуск» → ветка публикаций | Для рабочего выпуска передай слот, материал, версию и основания обоих одобрений. В текущем режиме передай только статус локальной проверки. |
| GATE 3 → 01 и реестр | При подтверждённом рабочем выходе верни фактическое время, платформу, URL или ID, опубликованную версию и дату проверки метрик, если применимо. |

Общие поля: FROM / TO, CYCLE ID / CYCLE RUN ID, RELEVANT ID, ASSET VERSION, STATUS, DATE, SUMMARY, REQUIRED ACTION. Сохраняй ссылку на вход, результат и решения Таты. Для отсутствующего обязательного поля укажи `DATA INSUFFICIENT` и причину. Полная схема находится в [HANDOFF_FIELDS](protocols/HANDOFF_FIELDS.md).
